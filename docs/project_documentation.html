Personal Paste / Notepad Project Documentation

Simple Hindi-English Guide

Yeh document project ke model fields, URLs, structure, save flow, slug generation, file upload, aur complete working ko simple language me explain karta hai.

1. Project Overview

Yeh project ek small Django based no-login notepad / pastebin app hai. User jab home page / open karta hai, app ek new note create karta hai aur user ko random private URL par redirect kar deta hai.

Jo person note ka URL jaanta hai, woh note read aur edit kar sakta hai. Is project me login system nahi hai, isliye privacy ka main control URL slug hai.

4. Database Model: Note

Project me main model sirf ek hai: Note. Isme note ka content, slug, attachment details, aur timestamps store hote hain.

FieldTypeDetails

5. Slug Generation Kaise Hota Hai

Slug create karne ka code views.py ke create_note() function me hai.

  1. Allowed characters: lowercase alphabets a-z aur digits 0-9.
  2. Slug length: 8 characters.
  3. Python secrets.choice() use hota hai, jo cryptographically strong random value deta hai.
  4. App Note.objects.create(slug=slug) se note save karta hai.
  5. Agar same slug already exist karta hai, database IntegrityError dega because slug unique hai.
  6. Collision aane par app dobara try karta hai. Maximum 10 attempts hote hain.
  7. 10 attempts fail hone par RuntimeError raise hota hai.

Simple words me: home page open karte hi app ek random private link banata hai, note database me save karta hai, aur user ko us link par bhej deta hai.

7. Note Save Flow

Frontend Side

  1. User textarea me type karta hai.
  2. note.js input event pakadta hai.
  3. Status Typing... show hota hai.
  4. App 5000 ms wait karta hai. Is delay ko SAVE_DELAY_MS kaha gaya hai.
  5. Agar content last saved content se different hai, browser POST /api/<slug>/ call karta hai.
  6. Request JSON body: {"content": "user text"}.
  7. CSRF token header X-CSRFToken ke through send hota hai.

Backend Side

  1. note_api() slug se note find karta hai.
  2. Expired large attachment hai to pehle remove kar sakta hai.
  3. JSON body parse hoti hai.
  4. Content string hona required hai. Agar string nahi hai to 400 error.
  5. Agar new content old content se different hai, only content aur updated_at save hote hain.
  6. Response me note payload return hota hai: slug, content, updated_at, attachment, aur changed flag.
Save optimized hai: frontend bhi same content save nahi bhejta, aur backend bhi unchanged content par unnecessary database update nahi karta.

8. Remote Refresh / Multi-tab Behavior

Frontend time-to-time GET /api/<slug>/ call karta hai. Agar note kisi aur tab/browser se update hua ho, current editor automatically latest content load kar leta hai.

Refresh interval user activity ke according change hota hai: active user ke liye fast refresh, idle user ke liye slow refresh. Hidden tab me polling stop ho jati hai.

9. File Upload Flow

  1. User Attach File button se file select karta hai.
  2. JavaScript FormData banata hai aur file key me selected file append karta hai.
  3. Browser POST /api/<slug>/file/ call karta hai.
  4. Backend transaction ke andar note ko select_for_update() se lock karta hai, taaki same time par conflicting upload/delete na ho.
  5. Agar note me already attachment hai, response 409 aata hai: pehle old file delete karni hogi.
  6. File save hoti hai, name, size, upload time database me store hote hain.
  7. Response me attachment payload return hota hai.

Attachment Path

Uploaded file ka path attachment_upload_path() function banata hai:

notes/<note-slug>/<random-32-hex><file-extension>

Example: notes/xqj25ft9/4af2...c91.pdf. Isse filename collision avoid hota hai aur files note slug ke folder me organize hoti hain.

10. File Delete And Download

ActionProcess
DeleteDELETE /api/<slug>/file/ call hota hai. Backend actual file delete karta hai, attachment fields empty karta hai, aur JSON me {"attachment": null} return karta hai.
DownloadGET /api/<slug>/file/download/ call hota hai. File available hai to FileResponse attachment ke form me return hota hai.
Missing fileAgar database me file record hai but disk par file missing hai, backend fields clear karta hai aur 404 return karta hai.

11. Large File Expiry

Is project me file size agar 5 MB se zyada hai, to file upload ke 3 hours baad expire ho jati hai.

Expiry check remove_expired_attachment() function karta hai. Yeh page open, API get/post, file upload/delete, aur download ke time call hota hai. Expired file milne par clear_attachment() actual file aur database fields clear kar deta hai.

16. Complete Working In Short

  1. User / open karta hai.
  2. Backend random slug se blank note create karta hai.
  3. User /<slug>/ editor page par redirect hota hai.
  4. User type karta hai, frontend 2 seconds baad changed content API ko bhejta hai.
  5. Backend content validate karke database me save karta hai.
  6. Frontend response ke baad status Saved show karta hai.
  7. User file attach kar sakta hai; one note me one file allowed hai.
  8. Large file 5 MB se zyada ho to 3 hours baad auto cleanup ho sakti hai.
  9. Same URL kisi aur ko share karne par woh bhi note read/edit kar sakta hai.

17. Important Points

  • Login/authentication nahi hai. URL jiske paas hai, access uske paas hai.
  • Slug strong random hai, but URL share carefully karna chahiye.
  • CSRF protection enabled hai for browser API requests.
  • Only one attachment per note supported hai.
  • Production me DJANGO_SECRET_KEY, DJANGO_DEBUG=False, HTTPS, aur proper host settings use karna chahiye.
